# AgriTwin-CPS 2.0

**Simulation-Based Greenhouse Digital Twin and Cyber-Physical Systems Research Platform**

[中文说明](README.zh-CN.md)

AgriTwin-CPS is a reproducible, simulation-based research platform for greenhouse digital twins
and cyber-physical systems. It models greenhouse environmental dynamics, maintains an estimated
virtual state from sensor observations, executes constrained irrigation and ventilation control,
and evaluates system behavior under sensor faults and communication failures.

The 2.0 research theme is **Sensor-Trust-Aware Adaptive Digital Twin**: assess per-channel
observation trust, estimate state under delays, and study sampling/error/resource tradeoffs.
The research question is whether model-assisted state estimation helps maintain environmental
control when observations are noisy, missing, biased, drifting or delayed. Improvements, ties and
degradation are all valid experimental outcomes. This project uses no reinforcement learning,
requires no greenhouse hardware and makes no claim of agronomic suitability, novelty or superiority.

Simulation environmental values are generated by the documented proxy model. External replay
retains measurements and labels their origin separately. `true_state` means simulator
truth, not a measured real-world state. Demonstration parameters have not been calibrated.

## Install

Python 3.11 or newer is required; the reference environment uses Python 3.11. Install from this
repository root with [uv](https://docs.astral.sh/uv/):

```bash
uv sync --frozen --extra dev --extra ui --no-editable
source .venv/bin/activate
```

The `ui` extra is optional. A regular wheel installation avoids platform-specific editable-path
issues; after editing package source, reinstall with
`uv sync --frozen --extra dev --extra ui --no-editable --reinstall-package agritwin-cps`.
Alternatively, use `python -m pip install '.[dev,ui]'` in a fresh virtual environment. `uv.lock`
records the resolved dependency versions. Core runs require no external API or network access
after dependency installation.

## Run simulations and experiments

Use a new output directory for each invocation; existing artifacts are never silently overwritten.

```bash
# Short, clean nominal simulation (4 hours)
agritwin simulate --config configs/nominal.yaml --steps 48 --output results/nominal_run

# Sensor dropout with a deterministic contiguous missing-data window
python scripts/run_simulation.py --config configs/sensor_dropout.yaml --output results/dropout_run

# Remote monitoring outage: the local control loop continues independently
agritwin simulate --config configs/communication_outage.yaml --output results/outage_run

# Same scenario and five seeds for both controllers (10 runs, 48 hours/run)
python scripts/run_experiment.py --name controller_comparison --output results/comparison_run

# Seven groups, 26 scenarios, 5 seeds, 2 controllers: 260 runs
python scripts/run_all_experiments.py --output results/suite_run --summary-plots-only

# Model-only estimator; still subject to the configured prediction-age safety limit
python -m agritwin_cps simulate --estimator model_only --output results/model_only_run
```

`--seeds 101 202 303`, `--seed 101` (single simulation), `--steps N`, `--controller threshold`
and `--config PATH` support explicit variations. `--no-plots` disables figure generation;
`--summary-plots-only` retains experiment comparison figures and skips individual trajectory figures.
The experiment runner applies predeclared scenario changes on top of the chosen configuration.
Use the clean default configuration for the documented protocol.

Each run writes the fully resolved YAML, seed/controller metadata, actual package source hashes,
trajectory CSV, observation/communication/actuator event tables, recovery events, metrics JSON,
terminal state, a units schema and a trajectory PNG. Experiments add per-seed metrics, mean/sample
standard deviation, paired controller differences, failure-case summaries and comparison figures.
CSV empty cells and JSON `null` mean not measured/not applicable; they never mean zero.
See [output conventions](docs/REPRODUCIBILITY.md) and [metric formulas](docs/METRICS.md).

## New 2.0 workflows

```bash
# Trust-weighted EKF with bounded replay and adaptive sampling; development seeds 11/22/33
agritwin simulate --config configs/adaptive.yaml --output results/trust_run

# Other A–H names: estimators, diagnostics, fault_severity, mismatch, budget, delay_loss, resources
agritwin adaptive --name sampling --config configs/adaptive.yaml --output results/sampling_study

# Handwritten format fixture: software validation only, not measured greenhouse evidence
agritwin replay --csv examples/format_fixture.csv --data-config configs/replay_example.yaml \
  --config configs/adaptive.yaml --output results/format_replay

# Four methods, paired masking seeds; measurement-agreement metrics, not hidden-truth errors
agritwin replay-experiment --csv examples/format_fixture.csv \
  --data-config configs/replay_example.yaml --config configs/adaptive.yaml \
  --seeds 11 22 33 --output results/format_comparison
```

`estimator.method` selects `model_only`, `observation_corrected`, `ekf` or `trust_ekf`.
`replay_history_steps` is an independent EKF switch (`0` disables). `health.method` selects
basic/residual/persistent diagnosis. `sampling.strategy` selects fixed/change/uncertainty/
trust_change/event; default fixed every step preserves the original baseline. All policies use
causal information and common time-indexed random draws. A/B/D/E/G comparisons use identical
fixed schedules; C/F/H study sampling/resource differences explicitly.

**Evidence includes negative results.** In the audited South African temperature replay, default
trust-EKF performs worse than ordinary EKF and fixed-gain correction under assumed forcing.
Heuristic trust is not a calibrated fault probability. Simulation resource savings vary by policy;
remote telemetry remains independent and is included in total bytes. Read
[results and limitations](docs/RESULTS.md) before interpreting any gain.

Public-data source/licensing, local audit, fixed segment selection and commands are in
[DATA_REPLAY.md](docs/DATA_REPLAY.md). Raw downloads and generated results are excluded from Git.

## Optional interface

```bash
streamlit run app.py
```

The **Digital Twin Research Laboratory** retains its four original workspaces and adds three:

- **Overview**: last successful experiment, actual state/MAE/violation metrics, and system data flow.
- **Simulation Lab**: six existing scenario presets, duration/time step/seeds, controller/estimator
  selection, noise/dropout and fault settings. Full YAML is optional under **Advanced Settings**.
- **State & Fault Analysis**: a shared time window for state layers, channel-specific errors,
  event evidence and requested/actual actions. Missing observations remain unconnected points.
- **Experiment Comparison**: actual UI or CLI results, every seed, mean/sample SD, paired deltas,
  censor counts and CSV/JSON downloads. One valid seed has undefined SD, not zero SD.
- **Sensor Trust & Sampling**: per-channel health, residuals/trust, sampling/send/delivery decisions,
  uncertainty safety flags and delayed-replay events, all from saved records.
- **Data Replay**: CSV mapping/preview/units, missing/delay experiments, replay comparisons,
  saved-result recovery and exports; clearly separates measurements from simulator truth.
- **Adaptive Experiments**: A–H variant selection and paired seeded comparisons with resource plots.

Select **Run Simulation** to execute; editing a control never starts an experiment. Results retain
an explicit saved configuration and a changed-draft warning. A failed attempt preserves the last
successful experiment and offers diagnostics. The white/black/gray theme uses a small blue accent
for scientific traces and distinct line/marker styles, rather than winner/loser color cues.

The interface calls the existing artifact runner and reads its saved metrics and trajectories;
it does not implement a second model or metric definition. Successful experiments persist under
`results/ui_runs/` with a completion manifest, per-seed artifacts, configurations, source/environment
metadata and summaries. Refresh restores the latest successful experiment; the sidebar can restore
older runs. Draft inputs persist across workspace navigation in the browser session, but a browser
refresh starts a fresh draft. Partial failed runs are never restored as successful results.

Export CSV/JSON or prepare a complete experiment ZIP. Existing CLI experiment directories under
`results/` are available in Experiment Comparison. Set `AGRITWIN_RESULTS_DIR` before starting the
app to choose a different local results root. Nothing is uploaded by the interface.

Evidence labels separate configured windows, recorded conditions, validation rejection, derived
fallback conditions and observed recovery. The separate health monitor produces heuristic
anomaly evidence; it does not establish sensor-fault causes. Fallback uses recorded validity,
age and EKF uncertainty, not command shape. Evaluator-only injection labels support simulated
diagnosis metrics; they never feed the estimator or sampler. Model-only estimates also obey the configured prediction-age fallback limit.

optional dependency is absent. See [research log](docs/RESEARCH_LOG.md) for actual validation records.

## Architecture and research scope

The plant and estimator share a pure model equation but have separate states, parameters and
initial conditions. The estimator receives only timestamped observations, applied-actuator
feedback and known synthetic weather. The controller receives readings or estimates and ages.
Only the sensor producer and evaluator observe simulator truth.

Remote telemetry never gates local control. Local sensor-link interruptions are a separate
experiment; both controllers fall back conservatively after configurable data-age limits.
This is application-layer message simulation, not validation of a real wireless link.
